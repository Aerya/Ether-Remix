# Ether v0.3.16

Highlights:

- **A permanent release library that never fetches the same NZB twice.** Every Usenet NZB and torrent record Ether resolves is now kept in a compressed release library, even when persistent media caching is turned off. Before searching indexers for a title, Ether checks qualifying releases already in the library, fetches NZBs from the library before asking any indexer, and remembers each release's archive layout so reopens skip archive discovery. Existing cached NZBs migrate automatically one file at a time (deduplicating copies across indexers, keeping archive passwords and setting unreadable files aside rather than deleting them). **Cache › Library** lets you search, check health, remove entries and import existing NZB backups from SABnzbd, NZBGet, a folder or a ZIP file without contacting any indexer, while **Cache › Overview** tracks library size and indexer grabs avoided. A new node-local **Release library limit** in Cache policy is unlimited by default and removes never-replayed releases first when set. In clusters, entries replicate across nodes (or share NAS storage) and snapshot incrementally into server backups.
- **Separate Home rows and per-library Recommended rows, plus custom library tabs.** Home Designer now focuses solely on Home, with a Rows-first layout and a Settings and Content drawer for each row. Each movie, TV and plugin library edits its own Recommended rows directly on its **Tabs** page instead of sharing one layout across libraries in Home Designer. Owners can add, reorder and edit tabs per library, group Collections tabs by any catalogue or plugin field (genres, studios, networks, decades, writers, ratings, runtime bands, resolutions and more), and choose a **Poster**, **Wide** or **Square** card shape.
- **Turn video transcoding off without losing direct play or Live TV.** A new node-local **Video transcoding** switch under **Playback › Streams & transcoding** disables video re-encoding for movies and shows while keeping direct play, remuxing, audio and subtitle conversion, and Live TV working normally. When off, Ether skips releases that would need video re-encoding and fails over to ones the device can play without re-encoding, or shows a clear message when none fits; Cluster status reflects nodes with video transcoding turned off.
- **One connection hub under Apps.** **Apps** replaces the old **General › How apps connect** section with one place for Ether's local, remote and Tailscale addresses, QR codes, per-app connection steps and port controls. Changing a dedicated app port switches its listener right away without a restart, and port-conflict warnings now name which other program on the computer is holding the port.
- **Brand Vela and manage skins.** **Apps › Vela** lets owners set a custom app name and light and dark wordmarks (PNG, SVG or WebP) with a live preview, and adds a **Skins** section listing built-in skins alongside custom .vskin packages uploaded or installed from a URL. You can pick a default skin or lock every Vela client to it, and Ether serves all skin files locally so apps never fetch third-party skin assets at runtime.
- **Automatic backup streams and steadier Live TV.** When the same channel appears more than once in your IPTV sources (another feed or another provider) and its guide matches, Ether adds the copies as automatic backup sources, ordered by provider priority, stream quality and live health. Your own edits and the backups you remove are kept. Backups appear after each source's next refresh. Steady channels build stability reserves smoothly at an imperceptible pace, hold through bursty or quiet provider pauses without fast-forwarding afterwards, reuse live provider connections instead of opening competing ones, and fix the live decoder deadlock and pacing drift that could freeze streams even while the provider was healthy and buffered.
- **App compatibility built from one shared registry.** **Playback › App compatibility** is reorganised into **Apps**, **Device profiles** and **Seen devices** tabs with compact single-line rows and search and filter toolbars. The **Apps** list is now generated directly from the same capability registry that serves playback, listing Plezy, Swiftfin, Infuse, Streamyfin, Findroid, Kodi, VLC and the Plex apps with their real built-in limits.

## Playback

- **Versions show their real audio tracks.** Before, version pickers guessed audio languages and channel layouts from release filenames, so multi-audio releases often showed incomplete or missing labels. When a viewer opens a title, Ether reads the container headers of its versions from sources it already has (releases in the release library and cached debrid files), never querying indexers, spending grabs or delaying playback. It stores the real tracks once per release and uses them to label versions in Plex, Jellyfin, Emby and Vela.
- **Anime prefers SeaDex-curated releases and maps more series.** Ether now applies a ranking boost for SeaDex-curated anime releases so well-regarded releases rank above uncurated ones while keeping Usenet and torrent copies from the same group on equal footing for fastest-source routing. Anime ID mapping also merges additional community datasets to fill gaps for seasons, cours and titles missing from the primary list.
- **Absolute-numbered anime finds the right releases in Stremio add-ons.** A regression in v0.3.15 queried Stremio add-ons with a non-standard season number for long absolute-numbered anime, finding fewer usable releases and sometimes accepting the wrong episode when an episode-order group started with Specials. Lookups now query the standard season-1 absolute form, episode-order groups that start with Specials keep their true season numbers, and releases whose absolute episode number disagrees with the requested episode are rejected (#613, thanks @kraigeisenman).
- **Non-English catalogues still match English release names.** When a server's catalogue language wasn't English, non-English originals carried only their localized and original titles, so releases named in English were rejected as a title mismatch. Ether now stores and matches the English title alongside the localized and original titles (#609, thanks @DarkyGuld).
- **Downloaded subtitles stay in sync across every app.** Downloaded sidecar subtitles are now aligned once per release (using embedded subtitle cues, speech timing or frame-rate correction) and cached so every app and repeat play receives the synced subtitle.
- **Automatic OpenSubtitles downloads run on Plex initial playback.** Plex clients that omitted profile headers or rotated session IDs between decision and start caused Ether to treat the subtitle selection as unverified and skip automatic OpenSubtitles downloads. Ether now carries the decision's client profile and selected subtitle into playback start (#459, thanks @arjanterheegde).
- **Embedded subtitles appear on the first play on Fire TV and Android Plex apps.** On Fire TV and Android HLS playback, an embedded SRT subtitle chosen automatically was marked selected in the decision without ever reaching the player. Ether now delivers embedded text tracks as WebVTT renditions inside the HLS stream so captions show from the very first play (#618, thanks @bmkhib).
- **Inherited household subtitle preferences appear in Plex.** Viewers who inherited the household's default subtitle mode and language without saving their own viewer-level rules were reported to Plex as manual with no default language. Plex accounts now reflect effective inherited audio and subtitle preferences (#617, thanks @kizit).
- **WebVTT tags no longer appear literally in SRT subtitles.** OpenSubtitles SRT files converted from WebVTT captions showed literal class, voice and language markup on screen in Plex for Apple TV and other SRT players. Ether now strips unsupported WebVTT tags and ruby annotations while preserving basic formatting, and cleans already-cached subtitles on read (#616, thanks @kizit).
- **Skipping a release for audio language still tries the next one.** When the first candidate was skipped for lacking the required audio language, Ether could abandon playback instead of moving to another working candidate, or fail under concurrent viewer policy updates. Ether now defers background probing until a release is adopted and keeps working fallbacks available across deadlines (#596, thanks @kraigeisenman).
- **Seeking mid-title no longer stalls copy streams.** Two copy-stream seek bugs are fixed: seeking forward into segments already written ahead of a paused copy run no longer deadlocks playback (#606, thanks @oleedv), and restarting a copy run mid-title with E-AC3 or AC3 audio now writes a complete initialization segment instead of leaving the player stalled waiting for the first chunk (#605, thanks @oleedv).
- **Hardware decoding works on Intel and AMD Linux hosts.** On Linux, informational video driver messages caused Ether's hardware decode check to treat every VAAPI and QSV decode probe as a failure and fall back to CPU decoding while keeping GPU encoding. Ether now ignores those informational lines so hardware decoding stays enabled.
- **Cleaner AAC audio and reliable owner-pinned sources.** Encoded AAC audio in HLS and DASH streams now stays cleanly timed across segment boundaries when converting from Matroska files. Owner-pinned releases whose health sample merely times out can now still start instead of failing outright, while confirmed broken releases remain rejected.
- **Cache eviction no longer stalls playback.** Evicting old segments from the disk cache used to run synchronously under a lock during writes, holding up playback and read-ahead. Eviction now runs asynchronously in a background worker (starting at 95% of budget down to 90%) so playback reads and writes stay smooth (#599, thanks @drondeseries).

## Console

- **Foreign age ratings count toward kids' limits, and rule fallbacks are clearer.** Foreign certifications (such as 18+, R18, Category III, X, Banned and regional scales) and uncertified restricted titles were treated as unrated and could slip past kids' and viewers' content-rating limits, or miss US rating filters like R, NC-17 and TV-MA. Ether now maps foreign certifications onto its enforcement scale without changing how ratings are displayed, and hides uncertified restricted titles from any viewer with a content-rating limit, even when unrated titles are allowed. In library and viewer rules, **Everything else** is now labelled **Titles not matched above**, and Show-only rule lists default unmatched titles to **Hide** automatically.
- **Opening Ether's root address in a browser opens the console.** Visiting the server's bare root address in a web browser used to return a raw 401 Unauthorized error instead of opening the console (#601, thanks @drondeseries). Bare browser visits now redirect to the console, while unknown paths across app protocols return 404.
- **MDBList setup, list imports and Home rows work reliably.** Turning on MDBList from the Integrations overview failed with a "no such config section" error, and one failing list could disrupt other imports. Overview toggles now open setup and save cleanly, MDBList list imports are isolated per list with per-list error reporting and smaller 100-item pages, and plugin or MDBList rows placed on Home populate properly in Plex (#602, thanks @aloft-coding).
- **A dedicated panel for Plex friends' watchlists, with calmer rate-limit handling.** Per-friend Plex watchlist statuses now live in a collapsible **Plex friends' watchlists** panel under **Viewers › Watchlists** with summary counts, rate-limit badges, search, **All / Issues / Synced** filters and a **Sync friends now** button. Plex Community requests also respect rate-limit cooldowns with exponential backoff and jitter, space out friend sharing calls, and handle cold title lookups cleanly (#603, thanks @drondeseries).
- **Faster PostgreSQL browsing and Plex shelves.** Large PostgreSQL catalogues now index artwork lookups for restricted viewers and episode release lookups for shelves and counts, and batch Plex metadata and hub queries so browsing and opening shelves stay fast (#598, thanks @drondeseries).

## Live TV

- **Private channels stay private.** Refreshing an IPTV or plugin source kept your enabled, favourite, rating and app choices for each channel but not Private, so the next automatic refresh (hourly) made private channels visible to every viewer again. Private is now kept like the rest.
- **Live channels keep a cushion against short hiccups.** A converted channel kept only about 2.5 seconds of video ready ahead of the player, and that shrank over time, so a half-second pause on a shared GPU (another viewer's transcode starting) could make the app rebuffer while Ether still held 15 seconds of the provider's stream. Ether now spends spare held-back video to build that lead up to 6 seconds without changing playback speed, and a brief encoder backlog no longer drops the picture rate.
- **Cleaner, steadier guide tabs in Plex.** Plex Live TV previously showed dozens of extra genre tabs that changed throughout the day alongside your own groups. Built-in categories and genre tabs are now deduplicated against your own group names, require at least three channels to appear, cap extra genres at eight, and derive channel membership across the full calendar day so tabs stay stable all day (#612, thanks @fatbob01).
- **Live TV plugins no longer time out during lineup and guide syncs.** Background lineup and guide refreshes for Live TV source plugins used to run under short viewer deadlines instead of the plugin's granted background limits, causing sports and other Live TV plugins to fail with deadline timeouts. Lineup and guide syncs now run on granted limits, and healthy plugins no longer carry stale past errors in health reports (#600, thanks @drondeseries).

## Usenet

- **Cross-indexer release identity and repost grouping.** Usenet releases are now identified across indexers by their actual segment message IDs once fetched, and by size, poster and upload day beforehand. A dead post or missing NZB is remembered across every indexer without extra grabs, and near-duplicate reposts collapse into one failover slot with the remaining copies kept as quiet fallbacks.
- **Active streams wait through brief provider backoffs.** When a Usenet provider briefly backed off, active streams could fail immediately instead of waiting for recovery. Active reads now hold up to 45 seconds for a serving provider to leave backoff, and release ranking steers new plays away from providers currently in backoff.
- **Misleading provider health checks are detected automatically.** Some Usenet providers report an article as present during a health check and then fail when Ether downloads the body. Ether now tracks per-provider agreement between health checks and real article downloads, stops trusting misleading checks on that provider until real downloads recover, and verifies articles honestly.

## Vela

Update Vela to **0.2.23 or later** (Apps › Vela) to use the new features below; older Vela versions keep working without them.

- **Sign in to Vela with a Plex account.** The server owner and active shared or home Plex users can now sign in to Vela using their Plex account, exchanging it for a Vela session while keeping server tokens and unshared accounts blocked.
- **Custom library tabs, grouped collections and card shapes.** Vela displays each library's owner-configured tabs, saved filtered views, Collections tabs grouped by any catalogue or plugin field, people directories, and **Poster**, **Wide** or **Square** card shapes.
- **Built-in skins serve directly from your Vela install.** Built-in skin files are served directly from the installed Vela client, and custom skin packages support both palette themes and full layout skins with long-lived local caching.

## Plugins

- **A busy plugin is no longer treated as crashed.** A plugin runs on a small pool of instances, and a viewer request that waited too long for a free one counted as a crash: Ether restarted the plugin, cancelled every job it was running and added a failure toward disabling it. A wait now answers "busy, try again in a few seconds" without touching the plugin's health or its jobs, background jobs always leave one instance free for viewers, and a plugin can ask for up to 4 instances, shown with its other runtime limits (#620, thanks @FizzWhirl).
- **Searching a newly added plugin library is fast.** A plugin library added after the database last gathered its statistics could take 19 seconds to search one word, because the database guessed the library was tiny and checked every item one by one. Search now always starts from the matching words, and the statistics refresh in the background after a library's first publish or when it grows several times over (#621, thanks @FizzWhirl).
- **A library plugin can also provide Live TV channels.** A content plugin can now add its own live channels to Live TV (for example, a games library with live esports channels) without a second, separate Live TV plugin.
- **Plugin libraries load a studio's or person's full catalogue on demand.** Plugins can seed a starter catalogue and expand a declared collection bucket or person only when a viewer opens it. The first open waits briefly for the first page of newest titles at viewer priority while the rest fills in the background, and listing tabs or single-item lookaheads never trigger unnecessary fills.
- **Plugin streams fail over across candidate sources.** Previously a plugin item opened a single stream with no mid-stream failover. Plugin items that provide multiple candidate sources now use Ether's shared playback failover pipeline, trying the next candidate automatically if one fails.
- **Frontend-adapter plugins can enforce your library rules and viewer limits.** Custom frontend adapters previously had no way to ask Ether which items a viewer was allowed to see, so library Hide rules didn't apply to their clients. Frontend-adapter plugins can now ask Ether which items are visible and browseable for the signed-in viewer, enforcing library grants, rules and safety limits (#615, thanks @FizzWhirl).
- **Faster publishing and opening for large plugin libraries.** Publishing a batch of items used to page through up to 50,000 existing items first, and opening filter lists aggregated every field row on every request. Ether now looks up only the affected item IDs and maintains precomputed filter tallies, speeding up publishing and filter opens on large plugin libraries (#607, #608, thanks @FizzWhirl).

## Apps

- **Converted streams play in Silo on Apple devices.** Silo's Apple app only authorizes playlist and segment addresses in one shape, and Ether named its stream variants differently, so every stream Ether converted or repackaged for Silo (a resume, Start Over, a seek, or any release Ether hadn't yet confirmed healthy) failed with "No compatible playback route" before the first picture. Ether now gives Silo addresses in the shape it accepts. Direct play was never affected.
- **Silo's library tabs and Continue Watching work properly.** In Silo, a library tab could say "Movies is empty" over a full library because Ether marked every section as featured and the app shows featured sections only in its hero, plugin library tabs failed to load, and Continue Watching cards had no progress bar because Ether left out the position and length. All three are fixed, Live TV channels in Silo's On Now row show their channel artwork instead of a blank TV icon, Explore all on a Silo row lists that row's titles instead of the whole catalogue, series pages offer Resume and show which episodes you've watched, and Silo's Favorites and Watchlist screens and favourite/watchlist buttons work.
- **Plezy gets 4K, HDR and Dolby Vision again.** Plezy on desktop and Apple devices was getting capped at 1080p because transcode-target limits in Plex client headers were restricting direct-play source selection, and native media reads that omit Plex headers fell back to a generic 1080p profile. Direct-play source selection now ignores transcode-only hints, headerless media reads inherit the viewer's recent device capabilities, and release explanations name what imposed a resolution ceiling.
- **Swiftfin's native player gets HDR HEVC instead of an SDR H.264 transcode.** Swiftfin's Apple native player requires fMP4 HEVC sample tags and master playlist resolution and frame-rate attributes; Ether previously checked codec tags against the source MKV and left those attributes off single-variant playlists, forcing HDR10 and Dolby Vision HEVC titles to transcode to SDR H.264. Ether now checks codec tags against the fMP4 output and includes resolution and frame-rate on single-variant HLS masters (#604, thanks @oleedv).
- **Jellyfin for Android TV no longer crashes on TV series pages.** Jellyfin Android TV 0.19.x crashed when opening show details because required fields (studio and person IDs, chapter image timestamps, stream types and Live TV user data) were missing or empty. Series responses now include the required fields, upcoming episodes for a series no longer return 404, client log uploads are accepted, missing images return 404 instead of 502, and browse pages fall back to unwatched defaults instead of failing with 503 if the watch-state database is busy (#614, thanks @krakenn9).
- **Jellyfin dashboard and library count pages load without 404 errors.** Opening the Jellyfin web dashboard, activity log, scheduled tasks, storage info or library item counts previously returned 404 Not Found. Ether now serves those dashboard and item-count pages cleanly for Jellyfin and Emby (#610, thanks @lordbeavis).
